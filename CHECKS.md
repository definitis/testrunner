# Проверки TestRunner

Проверено 20.10.2026 на Windows: Node.js 24.19.0, TypeScript 5.7.3,
g++ 14.2.0 (MinGW-w64), VS Code 1.142.0.

## Сборка и файлы

- `npm ci --ignore-scripts` и `npm run compile` выполнены успешно.
- Финальная сборка TypeScript после добавления примера прошла.
- `git diff --check` — без ошибок пробелов.
- Проверены вложенные пути с пробелами и кириллицей, разделение одноимённых
  исходников и отказ для пути вне проекта.
- Проверены номера, одиночный `.out`, параллельное создание двух пар,
  сохранность ранее записанных данных, числовая сортировка и игнорирование
  папок, названных как тестовые файлы.
- Проверены нормализация CRLF, пробелы в конце всего ответа и значимость
  начальных и внутренних пробелов.

## Компиляция и выполнение

Отдельная C++ программа была скомпилирована настоящим g++ один раз и запущена
с разными входами. Проверка функций запуска завершилась с кодом 0:

| Сценарий | Фактический результат |
| --- | --- |
| Верный ответ | PASS |
| Неверный ответ | FAIL |
| Ненулевой код при совпавшем stdout | ERROR, сохранён код 7 |
| Большой непрочитанный вход | Обработан без необработанного исключения stdin |
| Бесконечный цикл | TIMEOUT, около 3,02 секунды |
| Бесконечный вывод | ERROR по лимиту вывода |
| Диагностика stderr | Показана при ненулевом коде |
| Stderr при успешном завершении | Не влияет на сравнение stdout |
| Пустой вывод | PASS при пустом ожидаемом ответе |
| Нет исполняемого файла или `.out` | ERROR с причиной |

Также отдельно проверены диагностика неправильного C++, отсутствие g++ в PATH,
размещение бинарного файла во временной папке и удаление этой папки.
Исправлена обнаруженная ошибка Windows `write EOF`: раннее закрытие stdin
программой больше не подменяет её настоящий код возврата.

Первый успешный запуск при одной из проверок занял около 10,1 секунды вместе
с задержкой системного запуска Windows. Таймер процесса ставится после возврата
`spawn`; это не строгий предел общего ожидания вместе с работой ОС.

## Настоящий Extension Development Host

Через установленный VS Code запускались отдельные тестовые профили с
`--extensionTestsPath`. Сторонние расширения отключены. Применялся
`--disable-workspace-trust`, поэтому это проверки разрешённой рабочей области.
Оба набора проверок завершились с кодом 0.

Подтверждены активация, регистрация трёх команд, создание двух пар через
`Add Test` и фокус на `.in`. `Run All Tests` сохранила изменённые тестовые файлы,
скомпилировала программу и показала PASS/FAIL с итогом `1/2`.
После изменения исходника без ручного сохранения повторный запуск сохранил его,
пересобрал программу и показал изменившиеся ответы с итогом `0/2`.
Повторная одновременная команда не создала лишнюю компиляцию.

Второй набор проверил сообщения при отсутствии активного `.cpp`, файле вне
проекта, отсутствии тестов, ошибке компиляции и отсутствии `.out`.
После ошибки компиляции следующий запуск с исправленным исходником состоялся:
флаг выполнения корректно сбрасывается.

## Ограничения последнего npm test и демонстрации

**Последний общий `npm test` завершился с кодом 1.** Сборка, файловые проверки,
сравнение и основные сценарии выполнения прошли; запуск после повторной
компиляции изменённого тестового C++ исходника был заблокирован Windows
с ошибкой `UNKNOWN`. Этот сценарий ранее прошёл отдельно в Extension Host.
Последующие проверки ошибки компиляции и отсутствующего g++ выполнены отдельно.

Новый пример `examples/sum.cpp` успешно скомпилирован. Попытка запустить первый
демонстрационный тест также заблокирована Windows. Результаты `2/3` и `3/3`
именно этого примера в этой среде не подтверждены; в README указаны ожидаемые
результаты. Ответ `99` в третьем тесте оставлен намеренно неверным.

В журнале `Microsoft-Windows-CodeIntegrity/Operational` в 22:10 МСК
зафиксировано событие 3077 для созданного TestRunner `program.exe`:
политика Windows запретила его запуск. Настройки защиты не менялись,
повторный запуск заблокированного файла для обхода запрета не выполнялся.

## Не проверено запуском

- Работа на Linux.
- Ручной выбор файла в интерфейсе `Open Tests`.
- Отключение расширения именно в Restricted Mode: проверены декларация
  в манифесте и дополнительная проверка `workspace.isTrusted` в обработчиках.
- Отказ VS Code сохранить документ.
- Предел компиляции 30 секунд и лимит диагностики именно компилятора.
- Ручное нажатие F5; Extension Host проверялся через параметры командной строки.

Управление деревом дочерних процессов пользовательской программы
не поддерживается и не входит в эту реализацию.
