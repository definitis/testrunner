# TestRunner

Учебное расширение VS Code для проверки консольных программ C++17.

Установка зависимостей: `npm install`. Сборка: `npm run compile`.
Откройте эту папку в VS Code и нажмите F5 для запуска расширения.

## Тестовые файлы

В окне Extension Development Host откройте папку со своим сохранённым `.cpp`.
Сделайте вкладку исходника активной и через Ctrl+Shift+P выполните
`TestRunner: Add Test`. Откроются `test1.in` для входных данных и `test1.out`
для ожидаемого ответа. Заполняйте и сохраняйте их обычным редактором.
Перед добавлением следующего теста вернитесь во вкладку `.cpp`.

Тесты хранятся в `.testrunner/<имя исходника>/` внутри проекта.
Для `tasks/main.cpp` используется `.testrunner/tasks/main/`, поэтому вложенные
исходники с одинаковыми именами не смешивают тесты. Новые пары получают
следующий свободный номер и не перезаписывают существующие файлы.

`TestRunner: Open Tests` показывает список файлов тестов активного `.cpp`.
Удалять тесты можно через проводник VS Code, удаляя оба файла пары.
Тесты сохраняются после закрытия редактора.

## Запуск всех тестов

Сделайте `.cpp` активным и вызовите `TestRunner: Run All Tests` через Ctrl+Shift+P.
Расширение сохранит исходник и открытые изменённые файлы его тестов,
скомпилирует программу один раз и запустит её отдельно на каждом тесте.
Рабочей папкой программы будет папка исходника.

Панель **Output → TestRunner** покажет статус каждого теста, ожидаемый
и фактический ответ при `FAIL`, причину при `ERROR`/`TIMEOUT` и общий итог.
Итог также появится в небольшом уведомлении. При ошибке компиляции
в Output будет диагностика g++, а тесты запускаться не будут.
Повторная команда во время проверки не создаёт параллельный запуск.

## Компиляция C++

В `src/runner.ts` добавлена функция `compile`: она компилирует один исходник
через `g++ -std=c++17` и возвращает путь к программе во временном каталоге.
Функция `cleanup` удаляет этот каталог после использования.
Пути передаются отдельными аргументами без shell, поэтому пробелы в именах
не требуют ручного экранирования. Нужен установленный g++ в `PATH`.

Диагностика компилятора ограничена 1 МиБ, время компиляции — 30 секундами.
Ошибки компиляции и отсутствие g++ сообщаются отдельно. При ошибке временный
каталог удаляется. После тестирования он удаляется даже при проваленных тестах.

## Выполнение и сравнение

Функция `runTest` в `runner.ts` читает пару `.in`/`.out`, запускает готовую
программу отдельным процессом и передаёт содержимое `.in` в стандартный ввод.
Для каждого теста возвращаются ожидаемый и фактический вывод, статус и причина
ошибки, если она возникла:

- `PASS` — stdout совпал с ожидаемым ответом.
- `FAIL` — программа завершилась нормально, но stdout отличается.
- `ERROR` — отсутствует файл теста, не удалось запустить программу,
  код возврата ненулевой или вывод превысил 1 МиБ.
- `TIMEOUT` — программа не завершилась за 3 секунды.

При сравнении CRLF заменяется на LF, пробельные символы в конце всего вывода
отбрасываются. Пробелы в начале и внутри ответа учитываются. Вывод stderr
не сравнивается с ответом; при ошибке выполнения он включается в диагностику.
Ненулевой код возврата считается ошибкой даже при совпавшем stdout.

## Проверка проекта

Выполните `npm test`: команда собирает TypeScript и запускает небольшой
`test/smoke.cjs` с настоящим g++. Проверяются работа с файлами, сравнение,
основные статусы, таймаут, лимит вывода, непрочитанный вход, изменение кода,
ошибки компиляции, отсутствие ожидаемого ответа и компилятора.
Временные файлы после проверки удаляются. Тестовых библиотек не требуется.

Если политика Windows блокирует собранный `.exe`, скрипт завершится с ошибкой,
а не объявит проверку успешной. При `UNKNOWN` проверьте журнал Code Integrity.
