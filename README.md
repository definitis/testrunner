# TestRunner

Учебное расширение VS Code для проверки консольных программ C++17.

Автор: **Тимушев Виктор Алексеевич**

Группа: **М3110**

## Возможности

- `TestRunner: Add Test` — создать пару `.in`/`.out` и открыть её в редакторе.
- `TestRunner: Open Tests` — выбрать файл теста в стандартном списке VS Code.
- `TestRunner: Run All Tests` — скомпилировать активный `.cpp` и проверить все тесты.
- Статусы `PASS`, `FAIL`, `ERROR`, `TIMEOUT`, диагностика и итоговое уведомление.

## Требования и запуск через F5

Нужны VS Code 1.95 или новее на Windows или Linux, Node.js 22 или новее с npm
для сборки и компилятор g++ с поддержкой C++17 в `PATH`.
Проверьте в терминале: `node --version`, `npm --version`, `g++ --version`.
После изменения `PATH` перезапустите VS Code.

1. Откройте в VS Code именно папку `testrunner`, содержащую `package.json`.
2. Выполните в терминале:

   ```sh
   npm ci
   npm run compile
   ```

3. Нажмите F5 и при необходимости выберите **Run TestRunner**.
4. Откроется новое окно **Extension Development Host** с папкой `examples`.
   Если VS Code запросит доверие к этому собственному проекту, разрешите его.
5. Откройте `sum.cpp`. Команды доступны через Ctrl+Shift+P.

Расширение работает в новом окне. Для своей программы откройте в нём её папку
проекта. После изменения TypeScript остановите отладку и снова нажмите F5:
перед запуском задача `npm: compile` автоматически пересоберёт расширение.
Node.js для работы расширения встроен в VS Code; отдельный Node.js нужен
для установки зависимостей и команд npm при разработке.

## Тестовые файлы

В окне Extension Development Host откройте папку со своим сохранённым `.cpp`.
Сделайте вкладку исходника активной и через Ctrl+Shift+P выполните
`TestRunner: Add Test`. Откроются `test1.in` для входных данных и `test1.out`
для ожидаемого ответа. Заполняйте и сохраняйте их обычным редактором.
Перед добавлением следующего теста вернитесь во вкладку `.cpp`.

Тесты хранятся в `.testrunner/<имя исходника>/` внутри проекта.
Для `tasks/main.cpp` используется `.testrunner/tasks/main/`, поэтому вложенные
исходники с одинаковыми именами не смешивают тесты. Новые пары получают
следующий свободный номер и не перезаписывают существующие файлы.

`TestRunner: Open Tests` показывает список файлов тестов активного `.cpp`.
Удалять тесты можно через проводник VS Code, удаляя оба файла пары.
Тесты сохраняются после закрытия редактора.

## Запуск всех тестов

Сделайте `.cpp` активным и вызовите `TestRunner: Run All Tests` через Ctrl+Shift+P.
Расширение сохранит исходник и открытые изменённые файлы его тестов,
скомпилирует программу один раз и запустит её отдельно на каждом тесте.
Рабочей папкой программы будет папка исходника.

Панель **Output → TestRunner** покажет статус каждого теста, ожидаемый
и фактический ответ при `FAIL`, причину при `ERROR`/`TIMEOUT` и общий итог.
Итог также появится в небольшом уведомлении. При ошибке компиляции
в Output будет диагностика g++, а тесты запускаться не будут.
Повторная команда во время проверки не создаёт параллельный запуск.

## Компиляция C++

В `src/runner.ts` добавлена функция `compile`: она компилирует один исходник
через `g++ -std=c++17` и возвращает путь к программе во временном каталоге.
Функция `cleanup` удаляет этот каталог после использования.
Пути передаются отдельными аргументами без shell, поэтому пробелы в именах
не требуют ручного экранирования. Нужен установленный g++ в `PATH`.

Диагностика компилятора ограничена 1 МиБ, время компиляции — 30 секундами.
Ошибки компиляции и отсутствие g++ сообщаются отдельно. При ошибке временный
каталог удаляется. После тестирования он удаляется даже при проваленных тестах.

## Выполнение и сравнение

Функция `runTest` в `runner.ts` читает пару `.in`/`.out`, запускает готовую
программу отдельным процессом и передаёт содержимое `.in` в стандартный ввод.
Для каждого теста возвращаются ожидаемый и фактический вывод, статус и причина
ошибки, если она возникла:

- `PASS` — stdout совпал с ожидаемым ответом.
- `FAIL` — программа завершилась нормально, но stdout отличается.
- `ERROR` — отсутствует файл теста, не удалось запустить программу,
  код возврата ненулевой или вывод превысил 1 МиБ.
- `TIMEOUT` — программа не завершилась за 3 секунды.

При сравнении CRLF заменяется на LF, пробельные символы в конце всего вывода
отбрасываются. Пробелы в начале и внутри ответа учитываются. Вывод stderr
не сравнивается с ответом; при ошибке выполнения он включается в диагностику.
Ненулевой код возврата считается ошибкой даже при совпавшем stdout.

## Проверка проекта

Выполните `npm test`: команда собирает TypeScript и запускает небольшой
`test/smoke.cjs` с настоящим g++. Проверяются работа с файлами, сравнение,
основные статусы, таймаут, лимит вывода, непрочитанный вход, изменение кода,
ошибки компиляции, отсутствие ожидаемого ответа и компилятора.
Временные файлы после проверки удаляются. Тестовых библиотек не требуется.

Если политика Windows блокирует собранный `.exe`, скрипт завершится с ошибкой,
а не объявит проверку успешной. При `UNKNOWN` проверьте журнал Code Integrity.

## Демонстрационный пример

В `examples/sum.cpp` программа читает два числа и печатает сумму:

```cpp
#include <iostream>

int main() {
    long long a, b;
    if (!(std::cin >> a >> b)) {
        return 1;
    }
    std::cout << a + b << '\n';
}
```

Три теста находятся в `examples/.testrunner/sum/`:

| Тест | Вход | Ожидаемый ответ | Результат |
| --- | --- | --- | --- |
| test1 | `2 3` | `5` | PASS |
| test2 | `-7 4` | `-3` | PASS |
| test3 | `10 20` | `99` | FAIL: программа выводит `30` |

Третий ответ намеренно неверный. Пример вывода в Output:

```text
[PASS] test1
[PASS] test2
[FAIL] test3
Expected:
99
Actual:
30

Results: 2/3 passed
```

Для демонстрации преподавателю запустите пример, исправьте `test3.out` на `30`
и повторите команду из `sum.cpp`: должно получиться `3/3`. Добавьте четвёртый
тест через `Add Test`, например вход `7 -2` и ответ `5`, покажите созданные файлы.
Можно изменить `a + b` на `a - b` и запустить без ручного сохранения:
исходник сохранится, пересоберётся и результаты изменятся.

## Устройство расширения и структура проекта

VS Code запускает код расширений в отдельном процессе **Extension Host**.
`package.json` объявляет команды и точку входа `out/extension.js`.
При первом вызове команды VS Code активирует расширение через `activate`.
Функция `commands.registerCommand` связывает имя команды с обработчиком.
Через VS Code API обработчики получают активный документ, сохраняют и открывают
файлы, создают список выбора, уведомления и `OutputChannel`.

- `src/extension.ts` — три команды, редактор, сохранение, результаты и уведомления.
- `src/tests.ts` — вычисление путей, создание пар и поиск тестов по номерам.
- `src/runner.ts` — компиляция, процессы, ограничения и сравнение stdout.
- `package.json` — описание расширения, команды и команды npm.
- `package-lock.json` — зафиксированные версии зависимостей для `npm ci`.
- `tsconfig.json` — сборка TypeScript в JavaScript в папку `out`.
- `.vscode/` — конфигурация отладки F5 и задача сборки.
- `examples/` — демонстрационная C++ программа и три теста.
- `test/smoke.cjs` — небольшой проверочный скрипт без тестовых библиотек.
- `CHECKS.md` — фактически выполненные проверки и ограничения проверки.

Сторонних библиотек во время работы нет. Зависимости разработки нужны для
компилятора TypeScript и описаний типов Node.js и VS Code.

## Ограничения

Поддерживается один `.cpp`, без CMake и многофайловых проектов. Входы и ответы
читаются как UTF-8. Бинарный файл находится во временной папке. Пути передаются
отдельными аргументами `spawn` без shell.

Таймер процесса начинает действовать после возврата системного вызова запуска:
задержка Windows при создании процесса может увеличить общее ожидание.
Управление деревом дочерних процессов и изоляция программы не предусмотрены.

При открытии проекта программа не запускается. В недоверенной рабочей области
расширение отключено через Workspace Trust. Если Windows блокирует новый `.exe`
и Node.js сообщает `UNKNOWN`, выводится подсказка о журнале Code Integrity.
Настройки защиты расширение не меняет.
